# 엔진 컴포넌트 개발 가이드

- **폐기됨**
    
    # 엔진 내부 컴포넌트 추가 가이드
    
    ## 0) 먼저 결정해야 하는 정책 3가지
    
    컴포넌트 만들기 전에 이것부터 정하면 뒤에서 안 꼬임.
    
    1. **필수 컴포넌트인가?**
        - Transform처럼 필수면: `removable=false`, Add 메뉴 숨김
    2. **값 변경 시 후처리(불변식 유지)가 필요한가?**
        - Collider/AnimController/Renderer 대부분 필요함
    3. **기본 RTTR 직렬화로 충분한가?**
        - 충분하면 자동화로 끝
        - 생성자 인자/리소스 경로/PhysX 재구성 등 있으면 커스텀 serialize/deserialize 필요
    
    ---
    
    ## 1) 컴포넌트 타입 작성
    
    `src/Components/XXXComponent.h`
    
    ```cpp
    #pragma once
    #include<DirectXMath.h>
    
    namespace Alice
    {
    structColliderComponent
        {
    float radius =0.5f;
    bool  isTrigger =false;
            DirectX::XMFLOAT3 offset{0,0,0};
        };
    }
    
    ```
    
    ---
    
    ## 2) RTTR 등록 (자동 직렬화 기반)
    
    `src/Core/ComponentRegistry.cpp`의 `RTTR_REGISTRATION` 블록
    
    ```cpp
    #include<rttr/registration.h>
    #include"Components/ColliderComponent.h"
    
    RTTR_REGISTRATION
    {
    usingnamespace rttr;
    
        registration::class_<Alice::ColliderComponent>("ColliderComponent")
            .constructor<>()
            .property("radius", &Alice::ColliderComponent::radius)
            .property("isTrigger", &Alice::ColliderComponent::isTrigger)
            .property("offset", &Alice::ColliderComponent::offset);
    }
    
    ```
    
    - **기본 serialize/deserialize를 쓸 거면 RTTR 등록 필수**
    - 커스텀 serialize/deserialize로 “완전 수동”이면 RTTR 없어도 되지만, 
    팀 규칙으로는 그냥 등록하는 게 낫다(일관성/디버깅).
    
    ---
    
    ## 3) EditorComponentRegistry 등록 
    (저장/로드/Undo/Add 메뉴 자동화)
    
    `src/Core/ComponentRegistry.cpp`의 `RegisterEditorComponentsOnce()` 내부
    
    ### 3-A) 일반형(대부분)
    
    ```cpp
    auto& r = EditorComponentRegistry::Get();
    
    r.Register<ColliderComponent>(
    "Collider","Physics",
        [](World& w, EntityId e) { w.AddComponent<ColliderComponent>(e); },
    /*addable*/true,
    /*removable*/true,
    /*fileKey*/"Collider"
    );
    ```
    
    ### 3-B) 특수형(커스텀 serialize/deserialize 필요할 때)
    
    - 리소스 경로 상대화/절대화
    - 생성자 인자 필요
    - PhysX/애니 상태 재구성 필요
    
    ```cpp
    r.Register<MaterialComponent>(
    "Material","Rendering",
      [](World& w, EntityId e){
          w.AddComponent<MaterialComponent>(e, DirectX::XMFLOAT3(0.7f,0.7f,0.7f));
      },
    true,true,"Material",
    /*serialize*/[](const World& w, EntityId e){
    auto* m = w.GetComponent<MaterialComponent>(e);
    if (!m)return JsonRttr::json();
          MaterialComponent copy = *m;
          copy.assetPath = SceneSerializationHelpers::NormalizePathToRelative(copy.assetPath);
          rttr::instance inst = copy;
    return JsonRttr::ToJsonObject(inst);
      },
    /*deserialize*/[](World& w, EntityId e,const JsonRttr::json& j){
    if (!w.GetComponent<MaterialComponent>(e))
              w.AddComponent<MaterialComponent>(e, DirectX::XMFLOAT3(0.7f,0.7f,0.7f));
    
    auto* m = w.GetComponent<MaterialComponent>(e);
    if (!m)returnfalse;
    
          rttr::instance inst = *m;
    bool ok = JsonRttr::FromJsonObject(inst, j);
    
    // ✅ 중요: deserialize 안에서도 “불변식 유지 후처리”가 필요하면 여기서 한다.
    // 예: 리소스 리로드 / GPU 리소스 재생성
    
    return ok;
      }
    );
    ```
    
    ### 여기서 핵심 규칙 2개
    
    - **fileKey는 한번 정하면 변경 금지** (씬 파일 깨짐)
    - **후처리 필요하면 deserialize에도 넣어라**
        
        Undo/Redo/Load는 deserialize를 타니까, UI에서만 후처리하면 Undo 때 상태가 어긋남.
        
    
    ---
    
    ## 4) 인스펙터 구현 파일 작성 (EditorCore에 넣지 말고 분리)
    
    권장 위치: `src/Editor/Inspectors/ColliderInspector.cpp`
    
    ```cpp
    #include"EditorComponentRegistry.h"
    #include"World.h"
    #include"Components/ColliderComponent.h"
    // 필요하면 PhysicsSystem 헤더 등
    
    namespace Alice {
    
    staticvoidDrawCollider(World& w, EntityId e, InspectorUI& ui)
    {
    auto* c = w.GetComponent<ColliderComponent>(e);
    if (!c)return;
    
        ui.DragFloat("Radius", &c->radius,0.01f,0.0f,100.0f);
        ui.Checkbox("Is Trigger", &c->isTrigger);
        ui.DragFloat3("Offset", &c->offset.x,0.01f);
    
    if (ui.ev.changed)
        {
    // ✅ 불변식 유지 후처리(예: PhysX shape 갱신)
    // PhysicsSystem::Get().RebuildCollider(w, e);
        }
    }
    
    // 외부에서 호출될 “등록 함수” 하나만 공개
    voidRegisterColliderInspector()
    {
    auto& reg = EditorComponentRegistry::Get();
        reg.SetInspector<ColliderComponent>(
            [](World& w, EntityId e, InspectorUI& ui){DrawCollider(w, e, ui); },
    /*order*/0,
    /*exposeInspector*/true,
    /*exposeAddMenu*/true
        );
    }
    
    }// namespace Alice
    ```
    
    ### Undo/Redo는 어디서 처리되냐?
    
    - **여기서 PushCommand 하지 않는다.**
    - `EditorCore`가 공통으로:
        - `ui.ev.activated` 때 old snapshot
        - `ui.ev.deactivatedAfterEdit` 때 new snapshot
        - `desc.serialize/deserialize`로 Command 푸시
    - 그리고 너가 넣은 “존재 체크 가드” 덕분에 삭제된 컴포넌트가 Undo로 부활하는 것도 막혀있음.
    
    ---
    
    > 중요한 규칙: 인스펙터는 “값을 바꾸고 ui.ev를 올리는 역할” + “후처리”까지만 책임진다.
    > 
    
    ## 5) 인스펙터 등록 호출을 중앙에 연결
    
    `src/Editor/Inspectors/EditorInspectors.cpp` 같은 “등록 목록” 파일에서 호출
    
    ```cpp
    namespace Alice {
    voidRegisterColliderInspector();
    
    voidRegisterEngineInspectors()
        {
    RegisterColliderInspector();
    // RegisterAnimationControllerInspector();
    // RegisterMaterialInspector();
        }
    }
    ```
    
    그리고 `EditorCore` 초기화 시점에 한 번 호출:
    
    ```cpp
    RegisterEngineInspectors();
    ```

    ## 6) 놓치기 쉬운 체크리스트 (이거 빠지면 “왜 안 보임?” 됨)
    
    - [ ]  RTTR 등록 했나? (기본 직렬화 쓸 거면 필수)
    - [ ]  `RegisterEditorComponentsOnce()`에서 `r.Register<T>` 했나?
    - [ ]  인스펙터 파일에서 `reg.SetInspector<T>` 했나? (**이걸 안 하면 Add 메뉴에도 안 뜨게 막아둔 상태일 것**)
    - [ ]  인스펙터에서 `InspectorUI` 래퍼를 쓰나? (raw ImGui면 `ui.Capture(changed)` 직접 호출해야 Undo 트리거가 잡힘)
    - [ ]  후처리가 필요한 컴포넌트면
        - UI 변경 시 후처리 +
        - deserialize 시 후처리(Undo/Load도 포함)
            
            둘 다 들어갔나?

    # 최소 예시
    
    **엔진 내부 컴포넌트 추가 순서**는 아래 5줄로 요약됨:
    
    1. `Components/XXXComponent.h` 작성
    2. `ComponentRegistry.cpp`에 RTTR 등록
    3. `RegisterEditorComponentsOnce()`에 `r.Register<XXX>(..., fileKey, [optional ser/deser])`
    4. `Inspectors/XXXInspector.cpp`에서 `reg.SetInspector<XXX>(drawFn, ...)`
    5. `EditorInspectors.cpp`에서 `RegisterXXXInspector()` 호출 연결
