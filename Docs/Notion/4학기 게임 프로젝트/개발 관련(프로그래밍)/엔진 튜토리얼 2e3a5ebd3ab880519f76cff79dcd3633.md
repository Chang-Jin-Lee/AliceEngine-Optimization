        # 📝 [명세서] 머티리얼 속성 추가 및 셰이더 연동 가이드
        
        새로운 머티리얼 파라미터(예: `Emissive`, `RimLight`, `Dissolve` 등)를 추가하고 셰이더에 적용하는 표준 절차입니다.
        
        ## 1. 데이터 정의 (CPU 단계)
        
        ### 📂 `src/Components/MaterialComponent.h`
        
        구조체에 변수를 추가하고 **초기값**을 반드시 설정합니다.
        
        ```cpp
        struct MaterialComponent 
        {
            // ... 기존 변수들 ...
        
            // [Step 1] 변수 추가 (초기값 필수)
            float newParamByName = 0.0f; 
        };
        
        ```
        
        ---
        
        ## 2. 직렬화 및 파일 입출력 (JSON 연동)
        
        이 단계를 수행해야 에디터에서 값을 수정하고 `.mat` 파일로 저장/로드할 수 있습니다.
        
        ### 📂 `src/Core/ComponentRegistry.cpp`
        
        RTTR에 변수를 등록하여 자동 저장/로드 되게 합니다.
        
        ```cpp
        RTTR_REGISTRATION
        {
            using namespace rttr;
            registration::class_<MaterialComponent>("Alice::MaterialComponent")
                // ...
                // [Step 2] 프로퍼티 등록 (변수명과 문자열 키 일치 권장)
                .property("newParamByName", &MaterialComponent::newParamByName);
        }
        
        ```
        
        ### 📂 `src/Core/Material.cpp` (선택 사항)
        
        디버깅을 위해 `Load`와 `Save` 함수의 로그 출력 부분에 새 변수를 추가하면 좋습니다.
        
        ```cpp
        // MaterialFile::Load 및 Save 내부
        ALICE_LOG_INFO("... | NewParam: %.2f", ..., material.newParamByName);
        
        ```
        
        ---
        
        ## 3. GPU 데이터 전송 (Constant Buffer 업데이트)
        
        CPU에 있는 데이터를 GPU가 읽을 수 있는 버퍼(Constant Buffer)에 복사하는 단계입니다. **16바이트 정렬(Padding)**에 매우 주의해야 합니다.
        
        ### 📂 `src/Rendering/DeferredRenderSystem.cpp`
        
        **1) 구조체 정의 수정 (`UpdatePerObjectCB` 내부 또는 헤더)**
        셰이더의 `cbuffer` 구조와 정확히 일치해야 합니다.
        
        ```cpp
        struct CBPerObjectData
        {
            // ... 행렬 등 기존 데이터 ...
            
            // [Step 3-1] 데이터 추가
            float gNewParamByName; 
            
            // [중요] 전체 구조체 크기가 16바이트의 배수가 되도록 패딩 추가
            float gPad[3]; 
        };
        
        ```
        
        **2) 데이터 매핑 (Map/Unmap)**
        Component의 값을 CB 구조체로 복사합니다.
        
        ```cpp
        void DeferredRenderSystem::UpdatePerObjectCB(..., float newParam, ...)
        {
            // ... Map ...
            data->gNewParamByName = newParam;
            // ... Unmap ...
        }
        
        ```
        
        *(주의: `PassGBuffer` 등에서 `UpdatePerObjectCB`를 호출하는 모든 부분의 인자도 수정해주어야 합니다.)*
        
        ---
        
        ## 4. 셰이더 구현 (HLSL 단계)
        
        ### 📂 `src/Rendering/ShaderCode/DeferredShader.h` (또는 .hlsl 파일)
        
        C++ 구조체와 동일한 순서로 `cbuffer`를 정의하고 변수를 사용합니다.
        
        ```hlsl
        cbuffer cbPerObject : register(b0)
        {
            // ... 기존 변수들 ...
            
            // [Step 4] 변수 추가 (C++ 구조체 순서/크기와 100% 일치해야 함)
            float gNewParamByName;
            float3 gPad; // 패딩도 명시해주는 것이 안전함
        };
        
        // 픽셀 셰이더(PS) 등에서 사용
        float4 PS(...) : SV_Target
        {
            // ...
            float result = input.Color * gNewParamByName;
            // ...
        }
        
        ```
        
        ---
        
        ## ✅ 체크리스트 (작업 후 확인)
        
        1. **초기화 확인:** `MaterialComponent.h`에서 초기값을 넣었는가? (안 넣으면 쓰레기 값 들어감)
        2. **RTTR 등록:** `ComponentRegistry.cpp`에 등록했는가? (안 하면 저장 안 됨)
        3. **패딩 확인:** `DeferredRenderSystem.cpp`의 구조체 크기가 **16의 배수**인가? (HLSL 정렬 규칙 위반 시 렌더링 깨짐)
        4. **인자 전달:** `Render` 함수들에서 `UpdatePerObjectCB`를 호출할 때 새 값을 올바르게 넘겨주고 있는가?
        
        이 명세서를 복사해서 보관해 두시거나, 다음에 작업을 지시할 때 **"머티리얼 속성 추가 명세서에 따라 진행해줘"**라고 하시면 됩니다.
        
        미밑의 내용도 같이 보세요
        
        네, 정확합니다.
        
        `DEVICE_DRAW_CONSTANT_BUFFER_TOO_SMALL` 경고는 **"C++에서 `CreateBuffer`로 만든 버퍼 크기"**가 **"HLSL 셰이더가 선언한 `cbuffer` 크기"**보다 작을 때 발생합니다.
        
        즉, **Update 함수에서 데이터를 아무리 잘 넣어도, 최초 생성(`Initialize`) 시점의 버퍼 크기를 늘려주지 않으면** 이 경고가 뜹니다.
        
        요청하신 대로 이 주의사항을 포함한 **[최종 수정된 명세서]**입니다.

        # 📝 [통합 명세서] 머티리얼 속성 추가 및 셰이더 연동 표준 가이드 (v1.1)
        
        새로운 머티리얼 파라미터(예: `Outline`, `RimLight` 등)를 추가할 때, **데이터 정의 → 저장/로드 → GPU 메모리 할당 → 데이터 전송 → 셰이더**까지의 전체 흐름입니다.
        
        ## 1. 데이터 정의 (CPU 단계)
        
        ### 📂 `src/Components/MaterialComponent.h`
        
        컴포넌트 구조체에 변수를 추가하고 **초기값**을 반드시 설정합니다.
        
        ```cpp
        struct MaterialComponent 
        {
            // ... 기존 변수들 ...
        
            // [Step 1] 변수 추가 (초기값 필수)
            float newParam = 0.0f; 
        };
        
        ```
        
        ---
        
        ## 2. 직렬화 및 파일 입출력 (JSON 연동)
        
        에디터에서 수정하고 `.mat` 파일로 저장하기 위한 단계입니다.
        
        ### 📂 `src/Core/ComponentRegistry.cpp`
        
        RTTR에 변수를 등록합니다.
        
        ```cpp
        RTTR_REGISTRATION
        {
            using namespace rttr;
            registration::class_<MaterialComponent>("Alice::MaterialComponent")
                // ...
                // [Step 2] 프로퍼티 등록

        ```
        
        ---
        
        ## 3. GPU 구조체 정의 및 버퍼 생성 (⚠️ 중요: 오류 방지)
        
        **이 단계를 누락하면 `DEVICE_DRAW_CONSTANT_BUFFER_TOO_SMALL` 오류가 발생합니다.**
        데이터를 보내는 `Update` 로직뿐만 아니라, 그릇을 만드는 `Create` 로직도 수정해야 합니다.
        
        ### 📂 `src/Rendering/DeferredRenderSystem.h` (또는 관련 헤더)
        
        상수 버퍼(Constant Buffer)용 구조체 정의를 찾아서 수정합니다. (보통 `CBPerObject` 등의 이름)
        
        ```cpp
        // 셰이더로 보낼 구조체 정의
        struct CBPerObject
        {
            // ... 기존 행렬들 ...
            
            // [Step 3-1] 데이터 추가 (셰이더 순서와 동일하게)
            float gNewParam;
            
            // [Step 3-2] 16바이트(float4) 정렬 패딩 추가 (필수)
            // 예: float 1개 추가 시 -> float pad[3] 추가하여 16바이트 맞춤
            float gPad[3]; 
        };
        
        ```
        
        ### 📂 `src/Rendering/DeferredRenderSystem.cpp` - `CreateConstantBuffers()`
        
        버퍼를 생성하는 함수에서 `ByteWidth`가 갱신된 구조체 크기를 사용하는지 확인합니다.
        
        ```cpp
        bool DeferredRenderSystem::CreateConstantBuffers()
        {
            D3D11_BUFFER_DESC cbDesc = {};
            
            // [Step 3-3] sizeof(CBPerObject)가 수정된 구조체 크기를 반영하는지 확인
            // 구조체에 변수를 추가했다면 sizeof 값은 자동으로 커집니다.
            cbDesc.ByteWidth = sizeof(CBPerObject); 
            
            // 만약 sizeof를 쓰지 않고 하드코딩된 숫자(예: 256)를 썼다면 반드시 수정해야 함!
            
            // ... CreateBuffer 호출 ...
        }
        
        ```
        
        ---
        
        ## 4. 데이터 전송 (매 프레임/객체마다)
        
        ### 📂 `src/Rendering/DeferredRenderSystem.cpp` - `UpdatePerObjectCB()`
        
        CPU 컴포넌트 값을 GPU 버퍼 구조체로 복사합니다.
        
        ```cpp
        void DeferredRenderSystem::UpdatePerObjectCB(..., float newParam, ...)
        {
            D3D11_MAPPED_SUBRESOURCE mapped;
            // ... Map ...
            
            CBPerObject* data = (CBPerObject*)mapped.pData;
            
            // [Step 4] 값 대입
            data->gNewParam = newParam;
            
            // ... Unmap ...
        }
        
        ```
        
        ---
        
        ## 5. 셰이더 구현 (HLSL 단계)
        
        ### 📂 `src/Rendering/ShaderCode/DeferredShader.h` (또는 .hlsl)
        
        C++ 구조체와 **순서와 크기(패딩 포함)**가 100% 일치해야 합니다.
        
        ```hlsl
        cbuffer cbPerObject : register(b0)
        {
            // ... 기존 변수들 ...
            
            // [Step 5] 변수 추가
            float gNewParam;
            float3 gPad; // C++ 패딩과 일치시킴
        };
        
        // 픽셀 셰이더 사용 예시
        float4 PS(...) : SV_Target
        {
            return input.Color * gNewParam;
        }
        
        ```

        ## 🚨 트러블슈팅 (자주 발생하는 오류)
        
        ### ❌ 오류 메시지: `DEVICE_DRAW_CONSTANT_BUFFER_TOO_SMALL`
        
        > *"The size of the Constant Buffer ... is too small (256 bytes provided, 272 bytes, at least, expected)."*
        
        * **원인:** 셰이더(HLSL)에는 변수를 추가해서 크기(272)를 늘렸는데, C++ `CreateConstantBuffers()`에서는 아직 옛날 크기(256)로 버퍼를 만들었기 때문입니다.
        * **해결:**
        1. C++ 구조체(`CBPerObject`)에 변수와 패딩이 제대로 추가되었는지 확인한다.
        2. `CreateBuffer` 할 때 `ByteWidth = sizeof(CBPerObject)`가 최신 구조체 크기를 반영하는지 확인한다.
        3. **프로젝트를 재빌드(Rebuild)**하여 `sizeof` 값이 갱신되도록 한다.

        # 🎧 AliceRenderer Audio System Usage Guide
        
        이 문서는 `AliceRenderer`의 오디오 시스템을 구성하는 핵심 컴포넌트(`AudioSource`, `SoundBox`)와 이를 제어하는 예제 스크립트(`SetupExample`)의 사용법을 설명합니다.
        
        > **Note:** 최근 업데이트로 **Advanced Animation(블루프린트 등) 시스템이 제거**되었으며, 오디오 컴포넌트에는 **Visual Debugging(`debugDraw`)** 기능이 추가되었습니다.
        
        ---
        
        ## 1. AudioSource (단일 음원)
        
        `AudioSourceComponent`는 2D BGM이나 3D 공간 음향(SFX)을 재생하는 가장 기본적인 단위입니다.
        
        ### 1.1 `AudioSourceComponent` 구조
        
        * **역할**: 엔티티 위치에서 소리를 재생합니다.
        * **주요 속성**:
        * `soundPath`: 오디오 파일 경로 (예: `Assets/Sounds/Effect.wav`).
        * `is3D`: 3D 공간 음향 여부 (`true`면 거리에 따른 감쇠 적용).
        * `volume`: 소리 크기 (0.0 ~ 1.0).
        * `minDistance`: 감쇠가 시작되는 최소 거리 (이 거리 안에서는 최대 볼륨).
        * `maxDistance`: 소리가 들리는 최대 거리.
        * `debugDraw`: **[New]** 3D 감쇠 반경을 시각적으로 표시할지 여부.
        
        ### 1.2 `AudioSourceSetupExample` 스크립트 사용법
        
        이 스크립트는 `AudioSourceComponent`를 쉽게 설정하고, 런타임에 에디터 프로퍼티와 동기화하는 역할을 합니다.
        
        **[코드 패턴 및 동작 원리]**
        
        1. **초기화 (`Start`)**: `GameObject`에 `AudioSourceComponent`가 없으면 자동으로 생성(`AddComponent`)하고, 초기 프로퍼티 값을 설정합니다.
        2. **런타임 동기화 (`Update`)**: 에디터 UI(Inspector)에서 `minDistance`, `maxDistance`, `debugDraw` 등의 값을 변경하면 즉시 컴포넌트에 반영합니다.
        
        ```cpp
        // 사용 예시 (C++ Script)
        class AudioSourceSetupExample : public IScript
        {
            // ... 매크로 선언 ...
        public:
            // 에디터 노출 프로퍼티
            ALICE_PROPERTY(std::string, soundPath,    std::string("Assets/Sounds/Fire.wav"));
            ALICE_PROPERTY(bool,        is3D,         true); // 3D 사운드 활성화
            ALICE_PROPERTY(float,       minDistance,  2.0f);
            ALICE_PROPERTY(float,       maxDistance, 20.0f);
            ALICE_PROPERTY(bool,        debugDraw,    true); // 디버그 링 표시
        
            void Update(double dt) override
            {
                // 실시간으로 감쇠 거리 및 디버그 옵션 동기화
                if (auto* src = gameObject().GetComponent<AudioSourceComponent>())
                {
                    src->minDistance = minDistance;
                    src->maxDistance = maxDistance;
                    src->debugDraw = debugDraw;
                }
            }
        };
        
        ```
        
        **[DebugDraw 시각화 정보]**
        
        * `debugDraw = true` 설정 시 `DebugDrawSystem`을 통해 다음이 렌더링됩니다.
        * **녹색 링 (Green Ring)**: `minDistance` (감쇠 시작 지점)
        * **빨간 링 (Red Ring)**: `maxDistance` (소리가 소멸하는 지점)

        ## 2. SoundBox (영역 기반 음원)
        
        `SoundBoxComponent`는 특정 영역(AABB Box) 내부에 들어갔을 때 소리가 재생되거나 볼륨이 조절되는 환경음(Ambience) 시스템입니다.
        
        ### 2.1 `SoundBoxComponent` 구조
        
        * **역할**: 특정 박스 영역(`boundsMin` ~ `boundsMax`) 안에 `AudioListener`(카메라 등)가 들어오면 소리를 재생합니다.
        * **주요 속성**:
        * `boundsMin`, `boundsMax`: 로컬 좌표계 기준 박스 크기.
        * `edgeVolume`, `centerVolume`: 박스 가장자리와 중심부의 볼륨 보간.
        * `playOnEnter`, `stopOnExit`: 영역 진입/이탈 시 재생 제어.
        * `debugDraw`: **[New]** 박스 영역을 시각적으로 표시할지 여부.
        
        ### 2.2 `SoundBoxSetupExample` 스크립트 사용법
        
        환경음 박스를 배치하고 크기 및 디버그 모드를 제어합니다.
        
        **[코드 패턴 및 동작 원리]**
        
        1. `Start()`에서 컴포넌트가 없으면 생성하고 경로를 할당합니다.
        2. `Update()`에서 `debugDraw` 플래그를 지속적으로 동기화하여, 에디터에서 체크박스를 켜는 순간 박스 영역이 보이도록 합니다.
        
        ```cpp
        // 사용 예시 (C++ Script)
        class SoundBoxSetupExample : public IScript
        {
        public:
            ALICE_PROPERTY(std::string, soundPath, std::string("Assets/Sounds/ForestAmbience.wav"));
            ALICE_PROPERTY(bool,        debugDraw, false); // 기본은 끄고 필요할 때 켬
        
            void Update(double dt) override
            {
                auto go = gameObject();
                if (auto* box = go.GetComponent<SoundBoxComponent>())
                {
                    // 에디터에서 디버그 켜면 즉시 박스 렌더링
                    box->debugDraw = debugDraw;
                }
            }
        };
        
        ```
        
        **[DebugDraw 시각화 정보]**
        
        * `debugDraw = true` 설정 시:
        * **청록색(Cyan) 박스**: SoundBox의 실제 영역(World Space AABB)을 라인으로 그립니다.

        ## 3. 오디오 시스템 작동 흐름 (System Workflow)
        
        AliceRenderer의 오디오 시스템이 정상 작동하기 위한 조건입니다.
        
        1. **AudioListener 필수**: 씬 내에 `AudioListenerComponent`가 부착된 엔티티(주로 **Main Camera**)가 반드시 하나 있어야 합니다.
        * *Listener가 없으면 3D 사운드 계산(거리, 방향)이 불가능합니다.*
        
        2. **경로 (Path)**: 사운드 파일 경로는 실행 파일 기준 상대 경로(`Assets/...` 또는 `Resource/...`)를 사용해야 합니다.
        3. **업데이트 순서**:
        * `ScriptSystem`: `SetupExample` 스크립트가 실행되어 컴포넌트 값 갱신.
        * `AudioSystem`: 갱신된 컴포넌트(`AudioSource`, `SoundBox`) 데이터를 기반으로 FMOD/DirectSound 백엔드 제어.
        * `DebugDrawSystem`: `Render()` 단계에서 `debugDraw` 플래그가 켜진 컴포넌트의 시각화 처리.

        본 문서는 콘텐츠 프로그래머가 **Alice 엔진의 고급 애니메이션 시스템(Advanced Animation System)**을 사용하여 캐릭터의 이동, 전투, 상호작용을 구현하는 방법을 설명합니다.

        ## 1. 시스템 개요 (System Overview)
        
        이 시스템은 단일 애니메이션 재생을 넘어, **레이어(Layer)** 기반의 합성을 지원합니다.
        다음 컴포넌트들이 핵심 역할을 합니다:
        
        1. **`AdvancedAnimationComponent`**: 애니메이션 데이터를 처리하는 엔진 코어 컴포넌트입니다. (직접 수정하지 않고 스크립트로 제어합니다.)
        2. **`CharacterAnimatorComponent` (Script)**: 콘텐츠 프로그래머가 로직을 작성하는 곳입니다. 입력 처리, 상태 관리, 애니메이션 파라미터 설정을 담당합니다.
        
        ### 지원 기능 요약
        
        * **Locomotion Blend**: Idle ↔ Walk ↔ Run 자연스러운 전환.
        * **Upper Body Layering**: 하체는 걷고 상체는 조준/공격하는 분리 재생.
        * **Anim Montage & Notify**: 특정 시간(초)에 함수 실행(타격 판정 등) 및 재생 속도/방향 제어.
        * **Additive Animation**: 피격, 반동 등 기존 모션 위에 덧씌우는 애니메이션.
        * **IK (Inverse Kinematics)**: 손을 특정 위치에 고정하거나 발을 지면에 맞춤.
        
        ---
        
        ## 2. 필수 설정 (Setup)
        
        캐릭터 엔티티(Entity)는 반드시 다음 컴포넌트들을 가지고 있어야 합니다.
        
        1. `TransformComponent`: 위치/회전.
        2. `SkinnedMeshComponent`: 캐릭터 메쉬 (.fbx) 및 렌더링 데이터.
        3. **`AdvancedAnimationComponent`**: (스크립트에서 `AddComponent`로 자동 추가하도록 코딩하는 것을 권장)
        4. `CharacterAnimatorComponent` (사용자 스크립트)
        
        ---
        
        ## 3. 기능별 상세 가이드
        
        ### A. 기본 이동 블렌딩 (Locomotion Blend)
        
        두 개의 애니메이션(A, B)을 `blend01` 값(0.0 ~ 1.0)으로 섞습니다.
        
        * **사용처**: 대기(Idle)에서 걷기(Walk), 걷기에서 달리기(Run)로의 전환.
        * **단위**: `Time`(초), `Blend`(0.0: A재생, 1.0: B재생, 0.5: 반반 섞음).
        
        ```cpp
        // [설정 예시]
        anim->base.clipA = "Idle"; // A: 멈춤
        anim->base.clipB = "Run";  // B: 달리기
        
        // 입력이 있으면 blend 값을 1.0(B)으로, 없으면 0.0(A)으로 부드럽게 변경
        // SmoothApproach는 선형 보간(Lerp) 헬퍼 함수
        m_moveBlend = SmoothApproach(m_moveBlend, hasInput ? 1.0f : 0.0f, blendSpeed, dt);
        
        anim->base.blend01 = m_moveBlend;
        
        ```
        
        ### B. 상하체 분리 (Upper Body Layering)
        
        특정 본(Bone) 하위 계층에만 다른 애니메이션을 덮어씌웁니다.
        
        * **사용처**: 이동하면서 사격, 이동하면서 아이템 사용.
        * **주의**: 엔진 내부적으로 `Masked Bone`이 설정되어 있어야 합니다(예: `Spine` 이상).
        
        ```cpp
        // 이동 중일 때만 상체 레이어 활성화
        if (isMoving && isAiming) 
        {
            anim->upper.enabled = true;
            anim->upper.clipA = "Aim_Rifle"; // 조준 자세
            anim->upper.layerAlpha = 1.0f;   // 100% 적용
        }
        else
        {
            anim->upper.enabled = false; // 평소엔 끔 (기본 전신 애니메이션 사용)
        }
        
        ```
        
        ### C. 애님 몽타주 & 노티파이 (Montage & Notifies)
        
        애니메이션의 흐름을 스크립트가 완전히 제어합니다. 공격, 스킬, 상호작용 등 **특정 타이밍에 로직이 실행**되어야 하는 경우 사용합니다.
        
        * **핵심 로직**:
        1. `anim->base.autoAdvance = false`: 엔진의 자동 시간 흐름을 끕니다.
        2. `anim->base.timeA`: 스크립트에서 직접 시간을 더하거나 뺍니다(역재생).
        3. `anim->CheckAndFireNotifies(...)`: 수동으로 시간을 변경한 뒤 이벤트를 체크합니다.
        
        ```cpp
        // 1. 노티파이 등록 (Start 혹은 초기화 시점 1회 권장)
        if (!m_notifyRegistered) {
            // "Attack01" 클립의 0.7초 시점에 OnHit 함수 실행
            anim->AddNotify("Attack01", 0.7f, [this]() { this->OnHit(); });
            m_notifyRegistered = true;
        }
        
        // 2. 업데이트 루프 (Attacking 상태)
        if (m_state == CharState::Attacking)
        {
            float prevTime = m_animTime;
            m_animTime += DeltaTime * 1.5f; // 1.5배속 재생
        
            // 수동 제어 설정
            anim->base.autoAdvance = false;
            anim->base.clipA = "Attack01";
            anim->base.clipB = "Attack01";
            anim->base.timeA = m_animTime;
            anim->base.timeB = m_animTime;
        
            // 노티파이 트리거 (필수)
            anim->CheckAndFireNotifies("Attack01", prevTime, m_animTime);
        
            // 종료 체크
            if (m_animTime >= 2.0f) m_state = CharState::Standing;
        }
        
        ```
        
        ### D. 역재생 (Reverse Playback)
        
        몽타주 시스템을 활용하여 시간을 감소시키면 됩니다.
        
        * **사용처**: 앉았다가 다시 일어서기, 문 열었다 닫기 등.
        
        ```cpp
        // 일어서기 상태
        if (m_state == CharState::StandingUp)
        {
            m_animTime -= DeltaTime; // 시간을 뺌 (역재생)
            
            if (m_animTime <= 0.0f) {
                m_animTime = 0.0f;
                m_state = CharState::Standing; // 완료 후 상태 전환
            }
            
            anim->base.timeA = m_animTime; // 감소된 시간 적용
        }
        
        ```
        
        ### E. Additive Animation (반동/피격)
        
        현재 자세에 **'변화량'**만을 더합니다. (예: 조준 중 총기 반동으로 손이 뒤로 밀림)
        
        * **필수 조건**: `RefClip`(기준 포즈, 보통 Idle)과 `TargetClip`(변형 포즈)이 필요합니다.
        * **작동 방식**: `Result = CurrentPose + (TargetClip - RefClip) * Alpha`
        
        ```cpp
        if (isFiring)
        {
            anim->additive.enabled = true;
            anim->additive.clip = "Recoil";      // 반동 모션
            anim->additive.refClip = "Idle_Ref"; // 기준이 되는 포즈 (T-pose나 Idle 첫 프레임)
            anim->additive.time = m_recoilTimer; // 0.0초부터 재생
            
            m_recoilTimer += DeltaTime;
        }
        
        ```

        ## 4. 콘텐츠 프로그래머용 통합 템플릿 (Copy-Paste Ready)
        
        아래 코드는 위 기능들을 모두 통합하여 안전하게 작동하는 `CharacterAnimatorComponent`의 템플릿입니다. 콘텐츠 작업 시 이 구조를 따르십시오.
        
        ### `CharacterAnimatorComponent.h`
        
        ```cpp
        #pragma once
        #include "Core/IScript.h"
        #include "Core/ScriptReflection.h"
        #include <string>
        #include <DirectXMath.h>
        
        namespace Alice
        {
            // 상태 머신 정의
            enum class CharState { Standing, Crouching, Crouched, StandingUp, Attacking };
        
            class CharacterAnimatorComponent : public IScript
            {
                ALICE_BODY(CharacterAnimatorComponent);
            public:
                void Update(float DeltaTime) override;
        
                // --- 인스펙터 설정 변수 ---
                ALICE_PROPERTY(std::string, m_idleClip, "Idle");
                ALICE_PROPERTY(std::string, m_moveClip, "Run");
                ALICE_PROPERTY(std::string, m_crouchClip, "Crouch");
                ALICE_PROPERTY(std::string, m_attackClip, "Attack_Combo");
                
                ALICE_PROPERTY(float, m_crouchDuration, 1.0f);
                ALICE_PROPERTY(float, m_attackHitTime, 0.5f);
        
            private:
                void RegisterNotifies(); // 초기화 함수 분리
                void OnAttackHit();      // 타격 콜백
        
                CharState m_state = CharState::Standing;
                float m_animTime = 0.0f;       // 수동 시간 제어용
                float m_moveBlend = 0.0f;      // 이동 블렌딩용
                bool m_isInitialized = false;  // 초기화 플래그
            };
        }
        
        ```
        
        ### `CharacterAnimatorComponent.cpp`
        
        ```cpp
        #include "CharacterAnimatorComponent.h"
        #include "Components/AdvancedAnimationComponent.h"
        #include "Core/Input.h"
        #include "Core/Logger.h"
        
        namespace Alice
        {
            REGISTER_SCRIPT(CharacterAnimatorComponent);
        
            void CharacterAnimatorComponent::RegisterNotifies()
            {
                auto* anim = gameObject().GetComponent<AdvancedAnimationComponent>();
                if (!anim) return;
        
                anim->notifies.clear(); // 안전을 위해 초기화
                
                // 공격 클립의 특정 시간에 함수 연결
                anim->AddNotify(Get_m_attackClip(), Get_m_attackHitTime(), [this]() {
                    this->OnAttackHit();
                });
            }
        
            void CharacterAnimatorComponent::OnAttackHit()
            {
                ALICE_LOG_INFO("Hit Check! Frame: %f", m_animTime);
                // 여기에 데미지 처리, 이펙트 생성 등 작성
            }
        
            void CharacterAnimatorComponent::Update(float DeltaTime)
            {
                auto go = gameObject();
                if (!go.IsValid()) return;
        
                // 1. 컴포넌트 안전 확보 (없으면 추가)
                auto* anim = go.GetComponent<AdvancedAnimationComponent>();
                if (!anim) anim = &go.AddComponent<AdvancedAnimationComponent>();
        
                // 2. 초기화 (1회 실행)
                if (!m_isInitialized) {
                    RegisterNotifies();
                    m_isInitialized = true;
                }
        
                auto* input = Input();
                
                // ====================================================
                // [상태 머신 로직]
                // ====================================================
                switch (m_state)
                {
                case CharState::Standing:
                    {
                        // [이동 블렌딩 모드]
                        // 시스템이 자동으로 시간을 흐르게 함 (autoAdvance = true)
                        bool isMoving = input->GetKey(KeyCode::W) || input->GetKey(KeyCode::S) || ...;
                        
                        // 부드러운 블렌딩 처리
                        float targetBlend = isMoving ? 1.0f : 0.0f;
                        m_moveBlend += (targetBlend - m_moveBlend) * 10.0f * DeltaTime;
        
                        anim->base.enabled = true;
                        anim->base.autoAdvance = true;
                        anim->base.clipA = Get_m_idleClip();
                        anim->base.clipB = Get_m_moveClip();
                        anim->base.blend01 = m_moveBlend;
                        anim->base.speedA = 1.0f; 
                        anim->base.speedB = 1.0f;
        
                        // [상태 전이]
                        if (input->GetKeyDown(KeyCode::LeftControl)) {
                            m_state = CharState::Crouching;
                            m_animTime = 0.0f; // 시간 초기화
                        }
                        if (input->GetMouseButtonDown(MouseCode::Left)) {
                            m_state = CharState::Attacking;
                            m_animTime = 0.0f;
                        }
                    }
                    break;
        
                case CharState::Crouching: // 앉는 중 (정재생)
                    {
                        float prevTime = m_animTime;
                        m_animTime += DeltaTime; // 속도 조절 가능 (예: * 2.0f)
        
                        if (m_animTime >= Get_m_crouchDuration()) {
                            m_animTime = Get_m_crouchDuration();
                            m_state = CharState::Crouched; // 다 앉음
                        }
        
                        // [수동 제어 모드]
                        anim->base.autoAdvance = false;
                        anim->base.clipA = Get_m_crouchClip();
                        anim->base.clipB = Get_m_crouchClip(); // 블렌딩 없음
                        anim->base.timeA = m_animTime;
                        anim->base.timeB = m_animTime;
                        
                        // 노티파이 체크 (필요시)
                        anim->CheckAndFireNotifies(Get_m_crouchClip(), prevTime, m_animTime);
                    }
                    break;
        
                case CharState::Crouched: // 앉아 있음 (정지)
                    {
                        anim->base.autoAdvance = false;
                        anim->base.timeA = Get_m_crouchDuration(); // 마지막 프레임 고정
                        
                        // [상태 전이] 일어서기
                        if (input->GetKeyDown(KeyCode::LeftControl)) {
                            m_state = CharState::StandingUp;
                            // 시간은 현재(끝) 상태 유지한 채 시작
                        }
                    }
                    break;
        
                case CharState::StandingUp: // 일어나는 중 (역재생)
                    {
                        m_animTime -= DeltaTime; // 시간 감소
        
                        if (m_animTime <= 0.0f) {
                            m_animTime = 0.0f;
                            m_state = CharState::Standing; // 다 일어섬 -> 이동 가능
                        }
        
                        anim->base.autoAdvance = false;
                        anim->base.timeA = m_animTime;
                        anim->base.timeB = m_animTime;
                    }
                    break;
        
                case CharState::Attacking: // 몽타주 재생
                    {
                        float prevTime = m_animTime;
                        
                        // [속도 변형 예시] 0.5초 ~ 1.0초 구간은 느리게 재생 (슬로우 효과)
                        float speed = (m_animTime > 0.5f && m_animTime < 1.0f) ? 0.2f : 1.5f;
                        m_animTime += DeltaTime * speed;
        
                        anim->base.autoAdvance = false;
                        anim->base.clipA = Get_m_attackClip();
                        anim->base.timeA = m_animTime;
        
                        // 타격 판정 노티파이 실행
                        anim->CheckAndFireNotifies(Get_m_attackClip(), prevTime, m_animTime);
        
                        // 애니메이션 종료 체크 (하드코딩 된 길이 혹은 GetDuration 함수 활용)
                        if (m_animTime >= 2.0f) {
                            m_state = CharState::Standing;
                        }
                    }
                    break;
                }
            }
        }

        ## 5. 주의사항 및 오류 방지 (Troubleshooting)
        
        1. **클립 이름 오타 주의**:
        * `m_idleClip` 등 변수에 넣는 문자열이 `.fbx` 내부의 애니메이션 이름과 정확히 일치해야 합니다. (대소문자 구분)
        * 틀릴 경우 캐릭터가 T-Pose로 굳거나 크래시가 날 수 있습니다. (엔진 내부에 Fallback 처리가 되어있으나, 시각적으로 깨집니다.)
        
        2. **노티파이 시간 설정**:
        * 애니메이션 길이보다 긴 시간에 노티파이를 설정하면 영원히 호출되지 않습니다.
        * 역재생(`StandingUp`) 시에는 `prevTime > currTime`이 되므로, 현재 노티파이 로직(`prev < notify <= curr`)에서는 이벤트가 발생하지 않습니다. 역재생 시 이벤트를 원하면 로직 수정이 필요합니다.
        
        3. **상태 탈출 조건**:
        * `Attacking` 등 몽타주 상태에서 `Standing`으로 돌아오는 조건(시간 체크)을 빼먹으면 캐릭터가 영원히 굳어있게 됩니다.
        
        4. **Nullptr 체크**:
        * `GetAnimator()`, `GetComponent<>` 호출 후 반드시 유효성 검사를 하십시오. 엔진이 터지는 주범입니다.

        ### 📝 Alice Animation System 제어 명세서 (AI 작업 지시용)
        
        이 명세서는 `CharacterAnimatorComponent`와 `AdvancedAnimationComponent`를 사용하여 캐릭터 애니메이션을 제어하는 규칙과 주의사항을 정의합니다. 다른 AI에게 코드를 작성시킬 때 이 내용을 참고 자료로 제공하십시오.
        
        #### 1. 컴포넌트 구조 및 의존성
        
        * **제어 주체**: `CharacterAnimatorComponent` (사용자 스크립트)
        * **실제 구동**: `AdvancedAnimationComponent` (엔진 내부 컴포넌트)
        * **필수 헤더**: `<algorithm>`, `<cmath>`, `<functional>`, `Components/AdvancedAnimationComponent.h`
        * **등록**: `REGISTER_SCRIPT(CharacterAnimatorComponent);` 필수.
        
        #### 2. 레이어(Layer) 시스템 제어
        
        애니메이션은 3개의 레이어로 구분하여 제어해야 합니다.
        
        * **Base Layer (전신)**
        * `anim->base.enabled = true;`
        * `clipA`, `clipB`: 두 클립 간 블렌딩(`blend01`) 지원.
        * **자동 모드**: `autoAdvance = true` (일반 이동/대기). 엔진이 시간 관리.
        * **수동 모드**: `autoAdvance = false` (앉기 등 정교한 제어). `timeA`, `timeB`를 직접 업데이트해야 함.
        
        * **Upper Layer (상체)**
        * `anim->upper.enabled = true/false;`
        * 주로 조준(Aim), 제스처 등에 사용. 서 있을 때만 활성화하는 것을 권장.
        
        * **Additive Layer (보정/반동)**
        * `anim->additive.enabled = true/false;`
        * 사격 반동, 피격 등 **차분(Difference)** 애니메이션 적용.
        * `refClip`(기준 포즈)과 `clip`(변형 포즈)이 필요함.
        
        #### 3. 시간 제어 및 배속 구현 (핵심 로직)
        
        애니메이션 속도 조절은 `DeltaTime` 조작과 `speed` 파라미터를 조합하여 구현합니다.
        
        * **자동 진행(`autoAdvance = true`) 사용 시:**
        * `anim->base.speedA`, `anim->base.speedB`에 배속 값(float)을 직접 대입.
        * 예: `anim->base.speedA = 2.0f;` (2배속)
        
        * **수동 진행(`autoAdvance = false`) 사용 시:**
        * 스크립트 내 `float` 변수(예: `m_currentTime`)를 선언하여 관리.
        * `m_currentTime += DeltaTime * SpeedFactor;` 형태로 시간 누적.
        * 특정 구간(예: 1초~2초)만 속도를 다르게 하려면 `if`문으로 구간을 감지하여 `SpeedFactor`를 변경.
        
        #### 4. 노티파이(Notify) 처리
        
        애니메이션 특정 시점에 함수를 호출하려면 다음 규칙을 따릅니다.
        
        * **등록**: `Initialize` 혹은 `Update` 초기에 `m_notifyRegistered` 플래그를 사용하여 **한 번만** 등록.
        * **바인딩**: 람다 대신 `std::bind` 사용 권장 (가독성 및 디버깅 용이).
        ```cpp
        anim->AddNotify("ClipName", 0.7f, std::bind(&ClassName::FuncName, this));
        
        ```
        
        * **수동 제어 시 주의**:
        * `autoAdvance = false`일 때는 엔진이 노티파이를 자동 체크하지 않음.
        * 반드시 `anim->CheckAndFireNotifies(ClipName, prevTime, currTime);`를 호출해야 함.
        * 역재생(Rewind) 시에도 `prevTime > currTime` 상태로 호출하면 내부에서 역순 체크함.
        
        #### 5. IK (Inverse Kinematics) 제어
        
        * **Foot IK**:
        * 캐릭터의 `Transform`(캡슐)은 건드리지 않고, **Bone의 IK Target Position**만 변경하여 발을 움직임.
        * 부드러운 움직임을 위해 `std::lerp` 또는 `SmoothApproach` 함수 사용 필수.
        
        * **좌표계**:
        * `SetIK` 함수는 **모델 공간(Model Space)** 좌표를 사용 (캐릭터 발 밑이 (0,0,0)).
        
        #### 6. 코딩 컨벤션 및 주의사항 (Do & Don't)
        
        * **[Do]** `std::clamp`, `std::hypot` 등 C++20/17 표준 수학 함수 적극 활용.
        * **[Do]** `IsMoving` 체크 시 `1e-4f` 같은 엡실론 값 사용 (부동소수점 오차 방지).
        * **[Do]** 상태(State) 관리는 `enum class`를 사용하여 명확히 분리.
        * **[Don't]** `Update` 문 안에서 `AddNotify`를 매 프레임 호출하지 말 것 (중복 등록됨).
        * **[Don't]** 파일/클립 이름 문자열을 하드코딩하지 말고 `ALICE_PROPERTY`로 노출하여 에디터에서 수정 가능하게 할 것.

            ```cpp
            #pragma once
            #include <functional>
            
            namespace Alice
            {
            	template<typename... Args>
            	class Delegate
            	{
            	public:
            		using FunctionType = std::function<void(Args...)>;
            		
            		Delegate() = default;
            		
            		template <typename T>
            		void BindObject(T* instance, void(T::* method)(Args...))
            		{
            			m_callback = [instance, method](Args... args)
            			{
            				(instance->*method)(args...);
            			};
            		}
            
            		void BindLambda(FunctionType&& func)
            		{
            			m_callback = std::move(func);
            		}
            
            		void Unbind()
            		{
            			m_callback = nullptr;
            		}
            
            		void Execute(Args... args) const
            		{
            			if (IsBound())
            			{
            				m_callback(args...);
            			}
            		}
            
            		bool IsBound() const { return m_callback != nullptr; }
            
            	private:
            		FunctionType m_callback;
            	};
            
            	// 사용법: ALICE_DECLARE_DELEGATE(이름)
            
            	// 파라미터 0개
            #define ALICE_DECLARE_DELEGATE(DelegateName) \
                    using DelegateName = Alice::Delegate<>; 
            
            	// 파라미터 1개
            #define ALICE_DECLARE_DELEGATE_OneParam(DelegateName, Param1Type) \
                    using DelegateName = Alice::Delegate<Param1Type>;
            
            	// 파라미터 2개
            #define ALICE_DECLARE_DELEGATE_TwoParams(DelegateName, Param1Type, Param2Type) \
                    using DelegateName = Alice::Delegate<Param1Type, Param2Type>;

- NDC 상에서의 투명처리
    
    
    아래는 “NDC 상에서 투명처럼 보이게 하는 디더링(스크린‑도어)”을 어떻게 구현했는지, 어떤 좌표를 쓰고 어떤 로직이 들어갔는지 단계별로 정리한 설명입니다. 코드 흐름까지 상세히 적었습니다.
    
    ---
    
    **1) 왜 이런 방식이 필요한가**
    
    - 기존 방식은 [clip(alpha - 0.1)](https://file+.vscode-resource.vscode-cdn.net/c%3A/Users/User/.cursor/extensions/openai.chatgpt-0.4.68-universal/webview/#) 같은 **알파 테스트**(컷아웃) 방식이라,alpha < 0.1이면 바로 사라지고 alpha >= 0.1이면 갑자기 보입니다.
    - 우리는 “서서히 사라지는 느낌”을 원합니다.
    - 알파 블렌딩 대신 **NDC/SV_POSITION 기준으로 픽셀을 일부만 남기는 디더링**을 적용하면,픽셀 단위로 “점점 덜 그려지는 것처럼” 보여서 **가짜 투명(스크린‑도어 투명)**이 됩니다.
    
    ---
    
    **2) NDC에서 디더링을 한다는 의미**
    
    - 픽셀 셰이더 입력 SV_POSITION은 **이미 클립 공간 → NDC → 화면 좌표로 변환된 픽셀 위치**를 의미합니다.
    - HLSL에서 SV_POSITION은 보통 **화면 픽셀 좌표(정수에 가까운 값)**로 들어옵니다.
    - 이 좌표를 이용하면 “화면에 고정된 규칙적인 패턴”이나 “노이즈”를 만들 수 있습니다.
    - 즉, 오브젝트의 UV나 월드 좌표가 아니라 **화면 픽셀 단위**로“어떤 픽셀을 버릴지” 결정합니다.
    
    ---
    
    **3) 핵심 알고리즘 개요**
    
    1. 머티리얼 알파와 텍스처 알파를 곱해 alpha를 만든다.
        
        `alpha = textureAlpha * materialAlpha`
        
    2. 픽셀 좌표(SV_POSITION.xy)에 기반한 난수(노이즈) 값을 만든다.
    3. alpha가 낮아질수록 더 많은 픽셀이 clip()에 의해 버려지도록 한다.
        
        `if (alpha < 1)
            clip(alpha - threshold);`
        
        - threshold는 0~1 범위의 난수 (혹은 패턴값)이다.
        - alpha가 0.3이면, threshold가 0.3보다 큰 픽셀은 버려지고,0.3보다 작은 픽셀은 살아남는다.
        - 결과적으로 **약 30% 픽셀만 남는 효과** → 반투명처럼 보임.
    
    ---
    
    **4) 실제 구현 방식 (이번 수정 기준)**
    
    ### **(A) 디더 함수**
    
    우리는 기존의 4×4 Bayer 격자를 버리고 **노이즈 기반 해시**를 사용했습니다.
    
    Forward / Deferred 동일:
    
    `float DitherThreshold(float2 pos)
    {
        // Interleaved gradient noise (per-pixel hash, less visible grid)
        float n = 0.06711056f * pos.x + 0.00583715f * pos.y;
        return frac(52.9829189f * frac(n));
    }`
    
    - 입력: pos는 [SV_POSITION.xy](https://file+.vscode-resource.vscode-cdn.net/c%3A/Users/User/.cursor/extensions/openai.chatgpt-0.4.68-universal/webview/#)입니다. 즉 **화면 픽셀 좌표**입니다.
    - 내부에서:
        - pos를 특정 상수로 섞어 n을 만들고,
        - frac()로 0~1 범위 난수 비슷한 값으로 변환합니다.
    - 결과: **격자무늬가 덜 보이고 더 무작위처럼 보이는 투명**.
    
    ---
    
    ### **(B) 실제 픽셀 셰이더 적용**
    
    Forward PS와 Deferred PS 모두 아래 방식입니다:
    
    `float alphaTex = textureColor.a * gMaterialColor.a;
    
    // 텍스처 알파 컷아웃만 적용 (머티리얼 알파는 디더링)
    if (gUseTexture != 0)
    {
        clip(textureColor.a - 0.1f);
    }
    
    // 디더링 컷
    float alpha = saturate(alphaTex);
    if (alpha < 1.0f)
    {
        float threshold = DitherThreshold(input.Position.xy);
        clip(alpha - threshold);
    }
    
    // 이후에는 alpha를 1로 고정 출력
    float alphaOut = 1.0f;
    return float4(color, alphaOut);`
    
    ### 중요한 점
    
    - clip()은 **픽셀을 완전히 버리는** 함수입니다.
    - clip(alpha - threshold)는:
        - alpha가 threshold보다 작으면 버려짐
        - 크면 살아남음
    - 그래서 알파가 0.3이면 30% 픽셀만 살아남습니다 → 반투명처럼 보임.
    
    ---
    
    **5) 왜 NDC(SV_POSITION) 기준이 중요한가**
    
    - 오브젝트의 UV나 월드 좌표로 디더링하면, 카메라가 움직일 때 패턴이 고정되지 않고 “표면에 붙어서 흔들리는” 느낌이 납니다.
    - SV_POSITION 기반이면 **화면에 고정된 패턴**이므로더 안정적이고 “투명 느낌”에 가깝게 보입니다.
    - 그래서 “NDC 상에서 투명처럼 보이는 효과”라는 말이 나온 것입니다.
    
    ---
    
    **6) 왜 알파 블렌딩을 안 쓰는가**
    
    - 이 방식은 **진짜 알파 블렌딩이 아닙니다.**
    - 대신 “픽셀 일부를 버리는 방식”이므로
        - 깊이/정렬 문제를 피할 수 있고
        - 간단한 셰이더 수정만으로 투명 느낌을 얻습니다.
    - 단점은 디더 패턴(노이즈)이 남을 수 있다는 것인데,이번처럼 해시 노이즈로 바꾸면 훨씬 줄어듭니다.
    
    ---
    
    **7) 요약**
    
    - 머티리얼 알파를 곱해 alpha를 만든 뒤
    - 화면 픽셀 좌표(SV_POSITION) 기반 난수와 비교해서
    - clip()으로 일부 픽셀만 남겨서 투명처럼 보이게 했다.
    - 그 결과, 알파가 0→1로 변화할 때 점점 자연스럽게 사라지는 효과가 나온다.
