## 1. 아키텍처 개요

**AliceUI**는 현재 **DirectX 11 (D3D11)** 기반으로 완전히 전환되었습니다.

- **렌더링 엔진**: D3D11 SRV(Shader Resource View) + HLSL 픽셀 셰이더 사용 (직접 렌더링).
- **주요 경로**: `AliceRenderer/src/AliceUI/UIRenderer.h, .cpp`
- **레거시 (D2D)**: `UIWorldManager` 내부에 기존 데이터 저장/로드 호환용으로만 존재 (구 성빈님 작업분).
- **역할 분담**:
    - `UIWorldManager`: UI 씬 파일 관리, 초기화 흐름 담당.
    - `UIRenderer`: 실제 렌더링 및 효과 처리 담당.

## 2. 렌더링 파이프라인 및 셰이더

실질적인 모든 UI 렌더링(텍스처, 폰트, 버튼, 게이지)은 **D3D11 파이프라인**을 통해 이루어집니다.

### 2.1 셰이더 구조

- **소스 위치**: `AliceRenderer/src/AliceUI/UIShaderCode`
- **기본 구성**: 기본 픽셀 셰이더 및 그레이스케일 등 기초 효과 포함.
- **작동 방식**:
    1. `UIWidgetComponent.shaderName`으로 키값 설정.
    2. `UIRenderer::GetPixelShader(name)`에서 매핑된 셰이더 조회.
    3. 런타임에 `RegisterShader(name, source)`로 등록 가능.

### 2.2 드로우 콜 흐름

1. **버퍼 생성**: `RenderImage` / `RenderText` / `RenderGauge` 함수가 `UIVertex` 버퍼를 생성.
2. **렌더링 요청**: `DrawGlyphs` 함수 호출.
3. **GPU 제출**: `DrawGlyphs` 내부에서 픽셀 셰이더 설정 및 SRV 바인딩 후 쿼드(Quad) 출력.

## 3. 기능 확장 가이드

### 3.1 새로운 셰이더/효과 추가 방법

새로운 시각 효과를 넣으려면 다음 단계를 따르십시오.

1. **HLSL 소스 작성**: `UIShaderCode.h/.cpp`에 소스 코드 추가.
2. **엔진 등록**: `UIRenderer::RegisterShader("EffectName", source)` 호출.
3. **컴포넌트 연결**: UI 컴포넌트에서 `widget.shaderName = "EffectName"` 지정.
4. **파라미터 확장 (필요 시)**:
    - 현재 `UIConstants`(상수 버퍼)는 매우 단순함.
    - 강도, 색상, 시간 등의 파라미터가 필요하면 `UIRenderer`의 Constant Buffer 구조체를 확장하고, 렌더링 직전 업데이트 로직을 추가해야 함.

### 3.2 로직 및 컴포넌트 확장 위치

- **입력 처리**: `UIRenderer::UpdateButtonStates`
- **레이아웃 계산**: `UIRenderer::BuildScreenLayout`
- **렌더링 루프**: `UIRenderer::RenderScreen`, `RenderWorld`
- **새 컴포넌트 추가 (예: UIEffectComponent)**:
    - `Core/ComponentRegistry.cpp`에 **RTTR** 등록 필수.
    - `SceneFile.cpp`에서 직렬화(저장/로드) 처리 확인.

## 4. UI 애니메이션 및 연출 전략

### 4.1 구현 방식별 접근

| **구분** | **구현 방법** | **특징** |
| --- | --- | --- |
| **스크립트 제어** | `UITransform` / `UIText` 값 직접 갱신 | 간단한 흔들림, 튕김, 페이드 처리에 적합 |
| **전용 시스템** | `UIAnimationSystem` 별도 생성 | `UIRenderer::Update` 이전에 실행하여 자연스러운 연출 보장 |
| **셰이더 효과** | HLSL 픽셀 셰이더 조작 | 왜곡, 글로우, 쉐이더 기반 흔들림 등 고비용/복합 효과 |

### 4.2 효과별 추천 구현법

- **흔들림 (Shake)**: `UITransform.position` 업데이트 + Sine 함수 활용.
- **페이드 (Fade)**: `UIText` / `UIImage`의 `color.w` (Alpha) 조절.
- **그림자 (Shadow)**: 오프셋을 적용한 어두운 색상으로 텍스트/이미지를 1회 추가 렌더링.
- **글로우 (Glow)**: 셰이더를 통한 가우시안 블러 처리.
- **버튼 눌림**: `scale` 또는 `pivot` 조절.
- **게이지 애니메이션**: `UIGauge.displayedValue` 값을 보간(Lerp) 처리.

## ✅ 개발 체크리스트 (새 기능 추가 시)

기능을 구현할 때 다음 항목을 확인하세요.

- [ ]  **새 컴포넌트가 필요한가?**
    - [ ]  RTTR 등록 완료 (`ComponentRegistry.cpp`)
    - [ ]  직렬화 항목 추가 (`SceneFile.cpp`)
- [ ]  **새 셰이더가 필요한가?**
    - [ ]  `RegisterShader` 호출 및 `shaderName` 연결
- [ ]  **렌더링 파라미터(강도/시간 등)가 필요한가?**
    - [ ]  `UIConstants` 상수 버퍼 구조체 확장 및 업데이트 로직 추가

- AI가 정리해준 사용법 및 가이드
    
    ```python
    # AliceUI 시스템/사용법 가이드
    
    이 문서는 AliceRenderer의 **AliceUI 시스템 구조, 렌더링 파이프라인, 리플렉션/직렬화 방식, 에디터/스크립트 사용법**을 정리한 문서입니다. 다른 개발자가 바로 이해하고 사용하도록 구성했습니다.
    
    ---
    
    ## 1) 핵심 개요
    
    AliceUI는 엔진 `World` 위에 **UI 컴포넌트(UIWidget/UITransform/UIImage/UIText/UIButton/UIGauge)를 얹어** 렌더링하는 UI 시스템입니다.
    
    - **렌더링**: `AliceUI/UIRenderer`가 스크린 UI/월드 UI를 직접 그립니다.
    - **입력**: `UIRenderer::UpdateButtonStates`에서 클릭/호버를 계산합니다.
    - **직렬화/로드**: `Core/SceneFile` + `UIWorldManager`가 UI를 저장/로드합니다.
    - **리플렉션**: RTTR로 컴포넌트와 스크립트 필드를 등록합니다.
    
    주요 경로:
    - `AliceRenderer/src/AliceUI/*`
    - `AliceRenderer/src/Core/ComponentRegistry.cpp`
    - `AliceRenderer/src/Core/SceneFile.cpp`
    - `AliceRenderer/src/Editor/EditorCore.cpp`
    - `AliceRenderer/Assets/Scenes/*.scene` 및 `*.ui.scene`
    
    ---
    
    ## 2) 시스템 구성
    
    ### 2.1 UIWorldManager (기존 UI 저장/로드 관리)
    - 경로: `AliceRenderer/src/UI/UIWorldManager.*`
    - UI 전용 씬(`*.ui.scene`)을 저장/로드합니다.
    - 씬 로딩 시 `SceneFile::Load`/`LoadAuto`에서 `UIWorldManager::LoadUI()`가 호출됩니다.
    
    ### 2.2 UIRenderer (AliceUI 렌더러)
    - 경로: `AliceRenderer/src/AliceUI/UIRenderer.*`
    - 역할:
      - 스크린 UI 렌더링: `RenderScreen`
      - 월드 UI 렌더링: `RenderWorld`
      - 입력 처리: `UpdateButtonStates`
      - 텍스트 렌더링: `RenderText`
    
    렌더링 입력 흐름:
    1. `Engine`에서 매 프레임 `UIRenderer::Update(...)` 호출
    2. `BuildScreenLayout`로 UI 변환/좌표 계산
    3. `RenderScreen`/`RenderWorld`에서 컴포넌트별 렌더
    
    ---
    
    ## 3) UI 컴포넌트 구성
    
    모든 UI 컴포넌트는 `World`의 컴포넌트로 저장됩니다.  
    RTTR 등록은 `Core/ComponentRegistry.cpp`에 정의되어 있습니다.
    
    ### 3.1 공통 컴포넌트
    - `UIWidgetComponent`
      - 위젯 이름(`widgetName`)
      - 공간(`space`: Screen/World)
      - 가시성(`visibility`)
      - 상호작용 여부(`interactable`)
    
    - `UITransformComponent`
      - `anchorMin/anchorMax`: 앵커
      - `position`, `size`, `pivot`
      - `scale`, `rotationRad`
      - `sortOrder`
    
    ### 3.2 렌더 컴포넌트
    | 컴포넌트 | 역할 |
    | --- | --- |
    | `UIImageComponent` | 스프라이트/텍스처 표시 |
    | `UITextComponent` | 텍스트 표시 |
    | `UIButtonComponent` | 버튼 상태(일반/호버/눌림/비활성) |
    | `UIGaugeComponent` | 게이지 바 렌더링 |
    
    ---
    
    ## 4) 렌더링 파이프라인
    
    ### 4.1 스크린 UI 렌더링
    흐름: `UIRenderer::RenderScreen`  
    1. `BuildScreenLayout`으로 각 위젯의 world matrix와 AABB 계산  
    2. `UIImage/UIText/UIButton/UIGauge` 순서로 그리기  
    3. `sortOrder`로 정렬
    
    ### 4.2 월드 UI 렌더링
    흐름: `UIRenderer::RenderWorld`  
    월드 좌표를 그대로 사용하며, `billboard` 옵션 지원.
    
    ---
    
    ## 5) 텍스트 렌더링
    
    ### 5.1 Bitmap 폰트(.fnt)
    `UITextComponent.fontPath`가 `.fnt`이면 기존 `UIFont` 경로를 사용합니다.  
    이 경우 `UIFontCache`를 통해 텍스처와 글리프가 로드됩니다.
    
    ### 5.2 TTF/일반 폰트
    `.ttf`/`.ttc` 또는 빈 `fontPath`는 런타임 아틀라스를 만듭니다.
    - 폰트 바이트를 `ResourceManager::LoadBinaryAuto()`로 로드
    - `ImFontAtlas`에 `AddFontFromMemoryTTF`
    - D3D11 SRV 생성
    - **크기별 베이크 캐시**로 선명하게 렌더링
    
    기본 폰트 경로:  
    `Resource/Fonts/NotoSansKR-Regular.ttf`
    
    ---
    
    ## 6) 입력 처리 (버튼)
    
    ### 6.1 기본 방식
    `UIRenderer::UpdateButtonStates`에서 마우스 좌표와 UI AABB를 비교합니다.
    
    ### 6.2 에디터 뷰포트 보정
    에디터 모드에서는 Game 뷰포트가 창 안에 들어가므로,  
    **뷰포트 이미지 좌표 → 렌더 타겟 좌표**로 입력을 보정해야 합니다.
    
    관련 흐름:
    - `EditorCore`에서 Game 이미지 영역을 구함 (`ImGui::GetItemRectMin/Size`)
    - `UIRenderer::SetScreenInputRect(...)`에 **뷰포트 사각형 + 렌더 크기** 전달
    - 마우스는 `SetScreenMouseOverride()`로 **ImGui 좌표 기반으로 변환**
    
    게임 모드에서는 윈도우 전체가 렌더 타겟이므로 별도 보정이 필요 없습니다.
    
    ---
    
    ## 7) 리플렉션/직렬화 구조
    
    ### 7.1 RTTR 컴포넌트 등록
    UI 컴포넌트는 `Core/ComponentRegistry.cpp`에서 RTTR로 등록됩니다.  
    이 등록은 **에디터 Inspector 표시**와 **직렬화**에 사용됩니다.
    
    - `UIWidgetComponent`
    - `UITransformComponent`
    - `UIImageComponent`
    - `UITextComponent`
    - `UIButtonComponent`
    - `UIGaugeComponent`
    
    ### 7.2 Script 리플렉션 매크로
    스크립트의 RTTR 등록은 `Core/ScriptReflection.h`의 매크로로 처리합니다.
    
    - `ALICE_BODY(ClassName)` : 클래스 기본 등록
    - `ALICE_PROPERTY(Type, Name, DefaultValue)` : 필드 등록
    - `ALICE_FUNC(FuncName)` : 함수 등록
    
    ### 7.3 BindWidget 메타데이터
    `AliceUI/BindWidget.h`에서 BindWidget 관련 메타데이터를 정의합니다.
    
    - `UI_META_BIND_WIDGET`
    - `UI_META_OPTIONAL`
    - `UI_META_WIDGET_NAME`
    
    BindWidget 멤버는 직렬화에서 제외됩니다. (`JsonRttr`에서 BindWidget metadata 필드를 스킵)
    
    ---
    
    ## 8) 직렬화/로드 구조
    
    ### 8.1 World 씬 저장/로드
    - `SceneFile::Save/Load`에서 `World` 상태를 저장합니다.
    - UI 컴포넌트도 `World` 안에 들어가며, 저장 대상에 포함됩니다.
    
    ### 8.2 UI 씬 저장/로드
    - UI 전용 씬은 `*.ui.scene`으로 저장됩니다.
    - `UIWorldManager::SaveUI/LoadUI`가 담당합니다.
    
    ### 8.3 경로 정책
    `ResourceManager`는 논리 경로를 지원합니다.
    - `Assets/...`, `Resource/...`, `Cooked/...`
    - 절대 경로는 가능한 논리 경로로 정규화
    
    ---
    
    ## 9) 에디터 사용법
    
    ### 9.1 UI 생성

    ### 9.3 Inspector
    RTTR 기반 Inspector에서 UI 컴포넌트 값 수정이 가능합니다.

    ## 10) 스크립트 사용법 (BindWidget)
    
    ### 10.1 헤더에서 BindWidget 선언
    BindWidget은 **헤더에서 선언 + 등록**합니다.
    
    ```cpp
    class UIHudExample : public IScript
    {
    public:
        ALICE_BODY(UIHudExample);
        void Start() override;
        void Update(float dt) override;
    
        std::string rootWidgetName = "UI_Root";
    
        ALICE_BIND_WIDGET_NAMED(UIButtonComponent*, okButton, "OK_Button");
        ALICE_BIND_WIDGET_NAMED(UITextComponent*, titleText, "Title_Text");
        ALICE_BIND_WIDGET_OPTIONAL_NAMED(UIGaugeComponent*, hpGauge, "HP_Gauge");
    };
    ```
    
    ### 10.2 Start에서 바인딩
    ```cpp
    const auto result = AliceUI::BindWidgets(this, *world, root);
    if (result.missingRequired > 0) { /* 경고 처리 */ }
    ```
    
    ### 10.3 주의 사항
    - BindWidget은 **직렬화 대상이 아님** (로드 후 항상 재바인딩).
    - 바인딩은 **트리 생성 완료 이후**에 수행해야 합니다.
