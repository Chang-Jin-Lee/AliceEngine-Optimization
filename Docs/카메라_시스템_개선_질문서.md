# AliceRenderer 카메라 시스템 개선 설계 질문

## 현재 시스템 개요

### 아키텍처
- **ECS 기반**: Entity-Component-System 아키텍처 사용
- **스크립트 시스템**: `IScript`를 상속받는 스크립트들이 `LateUpdate(float lateDeltaTime)`에서 실행
- **컴포넌트 구조**:
  - `CameraComponent`: 기본 카메라 데이터 (primary, fovYRad, nearPlane, farPlane)
  - `TransformComponent`: 위치(position), 회전(rotation), 스케일(scale) - DirectXMath 사용

### 관련 헤더/경로 (최신 구조)
- `CameraComponent`: `Engine/src/Runtime/Rendering/Components/CameraComponent.h`
- `TransformComponent`: `Engine/src/Runtime/ECS/Components/TransformComponent.h`
- `CameraSystem`: `Engine/src/Runtime/Engine/CameraSystem.h/.cpp`

### 현재 카메라 스크립트들
1. **CameraManager**: 메인 카메라 관리 (CameraComponent의 primary 플래그 설정)
2. **CameraFollow**: 플레이어(SkinnedMesh)를 따라다니는 스크립트
   - `MoveOrbit()`: 마우스 드래그로 캐릭터 주변 회전 (구면 좌표계 기반)
   - `MoveDirectly()`: 고정 오프셋으로 직접 이동
   - `MoveLerp()`: 보간 이동 (현재 미사용)
3. **CameraMovement**: 방향키로 카메라를 직접 이동시키는 스크립트

### 현재 제약사항
- **트랜스폼 제어만 가능**: position/rotation만 직접 수정 가능
- **단일 카메라 모드**: 하나의 카메라만 제어하며 전환 기능 없음
- **고정된 카메라 설정**: FOV, 근거리/원거리 평면 등이 정적
- **충돌 처리 없음**: 벽 관통 방지, 오클루전 처리 없음

## 구현하고자 하는 핵심 기능

### 1. 다중 카메라 전환 시스템 (필수)
**요구사항**:
- 여러 개의 카메라를 미리 생성/설정해두고 런타임에 전환
- 카메라 전환 시 위치(position), 회전(rotation), FOV를 부드럽게 보간 (Lerp/Slerp)
- 전환 시간(duration) 및 이징 곡선 제어 가능

**기술적 질문**:
- ECS 구조에서 여러 카메라 엔티티를 관리하는 최적의 방법은?
- 보간 중인 카메라의 TransformComponent를 어떻게 처리해야 할까? (별도 중간 상태 저장 vs 현재 카메라에 직접 보간)
- CameraComponent의 primary 플래그 전환 타이밍은? (보간 시작 전/후?)
- 여러 카메라의 상태를 저장/로드하는 방식은? (씬 파일에 통합?)

### 2. 카메라 쉐이크 시스템 (필수)
**요구사항**:
- 전투/피격 시 화면 흔들림 효과
- Perlin Noise 또는 Random Offset 기반 노이즈 생성
- 강도(intensity), 지속 시간(duration), 감쇠(decay) 파라미터 제어
- 기존 카메라 로직(Follow 등)과 쉐이크를 어떻게 합성할지?

**기술적 질문**:
- 쉐이크를 TransformComponent에 직접 더할지, 별도 오프셋 레이어로 분리할지?
- 쉐이크가 다른 카메라 스크립트(CameraFollow 등)와 충돌하지 않도록 하는 방법은?
- 쉐이크 애니메이션 커브(진폭 감쇠 등)를 시간 기반으로 구현할 때 최적 구조는?

## 추가 기능 (우선순위 높음)

### 3. 스프링 암 (Spring Arm) - 벽 관통 방지
**요구사항**:
- 카메라와 타겟(플레이어) 사이 Ray/Sphere Cast로 장애물 감지
- 장애물 발견 시 카메라를 타겟 쪽으로 당겨서 거리 조절
- 지형 끼임 방지 (최소 높이/바닥 클램프)

**기술적 질문**:
- PhysX가 있는 것으로 보이는데, Ray Cast는 PhysX를 활용해야 할까, 아니면 직접 구현?
- 스프링 암 로직을 CameraFollow에 통합할지, 별도 컴포넌트로 분리할지?
- 보간 전환 중인 카메라에도 스프링 암을 적용해야 하는가?

### 4. 락온(Lock-On) 시스템
**요구사항**:
- 타겟 선정: 거리, 화면 중심, 시야각, 가시성(Line of Sight) 기반
- 타겟 유지: 화면 밖 이탈 방지, 거리 자동 조정
- 타겟 스위치: 좌/우 입력으로 인접 타겟 전환
- UI 연동: 월드→스크린 변환으로 락온 마커 위치 제공

**기술적 질문**:
- 락온 상태와 일반 Follow 상태를 어떻게 전환? (상태 머신 vs 플래그)
- 타겟 후보군을 매 프레임 스캔할지, 이벤트 기반으로 관리할지?
- WorldToScreen 변환은 어디에 구현? (렌더링 시스템과의 연동)

### 5. 카메라 상태 머신 (모드 전환)
**요구사항**:
- 상태: Explore / Combat / LockOn / Aim / BossIntro / Death 등
- 상태 간 블렌딩: 위치, 회전, FOV를 각각 Lerp/Slerp로 부드럽게 전환
- 상태별 카메라 파라미터 저장/복원

**기술적 질문**:
- 상태 머신을 별도 컴포넌트로 만들지, CameraManager에 통합할지?
- 상태 데이터(CameraComponent + Transform 설정)를 어떻게 직렬화/저장?
- 상태 전환 중 사용자 입력(마우스 회전 등)을 어떻게 처리?

### 6. 동적 FOV (Field of View)
**요구사항**:
- 달리기/치명타/저스트 회피 시 FOV 자동 변경
- 시간 기반 보간으로 부드러운 전환

**기술적 질문**:
- FOV 변경을 CameraComponent.fovYRad에 직접 적용할지, 별도 오버라이드 레이어로?
- FOV 애니메이션을 상태 머신과 어떻게 연동?

### 7. 오클루전 디더링
**요구사항**:
- 카메라와 캐릭터 사이 장애물 발견 시, 카메라를 당기는 대신 장애물을 반투명 처리
- 머티리얼 파라미터 또는 후처리 기반 투명도 조절

**기술적 질문**:
- 오클루전 감지는 스프링 암과 동일한 Ray Cast로?
- 반투명 처리는 렌더링 파이프라인에서 어떻게 구현? (CameraComponent에 관련 데이터 추가?)

### 8. 슬로우 모션 (Time Dilation)
**요구사항**:
- '저스트 회피' 성공 시 TimeScale 조절
- 카메라 움직임도 함께 느려지거나 강조

**기술적 질문**:
- TimeScale을 글로벌로 관리할지, 카메라별로 관리할지?
- deltaTime 곱셈 위치는 어디가 적절?

## 코드베이스 특이사항

- **DirectXMath 사용**: `DirectX::XMFLOAT3`, `DirectX::XMConvertToRadians` 등
- **TransformComponent.rotation**: 라디안 단위 (SetRotation은 도→라디안 변환)
- **ScriptFactory**: `REGISTER_SCRIPT()` 매크로로 스크립트 등록
- **World::GetMainCameraEntityId()**: primary=true인 CameraComponent를 가진 엔티티 반환
- **GameObject::FindFirstSkinnedMesh()**: 타겟 찾기 메서드
